# Security Policy

## Reporting a Vulnerability

Please do not report security vulnerabilities through public GitHub issues.

If you believe you have found a security vulnerability in kairOS, please report it privately to the project maintainers.

Use the repository's GitHub **Security** tab to submit a private vulnerability report if available.

If private vulnerability reporting is not enabled, contact the project maintainers through the security contact listed in the repository.

Please include as much information as possible, including:

- A description of the vulnerability
- The affected component or version
- Steps to reproduce the issue
- Potential impact
- Any relevant logs, configuration, or proof-of-concept code

Please avoid including sensitive information that is not necessary to reproduce or understand the vulnerability.

## What to Expect

We will acknowledge receipt of a vulnerability report as soon as reasonably possible.

The maintainers will investigate the report, determine its impact, and coordinate a fix where appropriate.

Depending on the severity and affected components, we may publish a security advisory and coordinate disclosure with relevant upstream projects.

## Scope

This policy covers security vulnerabilities in kairOS-specific code, build configuration, build infrastructure, and other project-controlled components.

Security issues in third-party software included or referenced by kairOS should generally be reported to the relevant upstream project as well. kairOS may coordinate with upstream maintainers when the issue affects the distribution.

## Disclosure

Please allow the maintainers reasonable time to investigate and address a vulnerability before publicly disclosing it.

Once a fix or mitigation is available, the project may publish relevant security information through GitHub Security Advisories or other appropriate project channels.

## Supported Versions

Security fixes are generally provided for actively maintained kairOS releases.

The supported versions and their maintenance status are documented in the project repository.
