# Contributing to kairOS

Thank you for your interest in contributing to kairOS.

kairOS is an open-source Linux distribution focused on agentic computing. 
Contributions to the build system, configuration, packages, documentation, and other parts of the project are welcome.

## Getting Started

Before making a contribution:

1. Read the [README](README.md) to understand the project.
2. Check existing issues and pull requests to see whether your contribution is already being discussed.
3. For significant changes, open an issue first so the approach can be discussed before implementation.

## Making Changes

Keep changes focused and avoid unrelated modifications in the same pull request.

When contributing:

- Follow the existing structure and conventions of the repository.
- Keep build recipes and configuration as simple and reproducible as possible.
- Document non-obvious behavior or configuration.
- Update relevant documentation when behavior changes.
- Test changes locally before submitting a pull request.
- Do not include generated build artifacts unless specifically required.
- Preserve the copyright and license information of third-party software.

## Pull Requests

Pull requests should:

- Clearly describe what has changed.
- Explain why the change is needed.
- Include relevant testing information.
- Keep the scope of the change focused.
- Update documentation where appropriate.

Maintainers may request changes before a pull request is merged.

## Issues

Use GitHub Issues to report bugs, request features, or discuss improvements.

When reporting a bug, include enough information to reproduce it, including where relevant:

- kairOS version
- Hardware
- Build configuration
- Steps to reproduce the issue
- Expected behavior
- Actual behavior
- Relevant logs or error messages

Do not include sensitive information in issues.

## Code of Conduct

Please be respectful and constructive when participating in the project.

Harassment, discrimination, personal attacks, and other unacceptable behavior are not welcome.

Project maintainers may remove contributions or restrict participation when necessary to maintain a constructive project environment.
